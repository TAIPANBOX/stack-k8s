# stack-k8s 1.11.0

A minor release that moves the pins. TokenFuse v1.25.0 lets a person's delegation ride beside an agent's own token, and the Go services the stack runs are rebuilt on Go 1.27.4: wardryx, heraldyx, idryx, keyryx, scopyx, typryx, costcrew, agent-conform and qryx. vouchryx v0.8.0 (scoped revoke keys) joins them. No manifest changes shape and nothing needs a migration.

## Upgrade first

1. **Re-run the launcher, or apply the manifests of this tag.** Nothing else moves: no new object, no changed claim, no new setting. Images move by tag and digest:

The manifests of this tag pin the console image they pinned before, `genaryx-console:v1.8.8`.
2. **TokenFuse v1.25.0 adds two request headers and changes nothing for a client that sends neither.** Under `TOKENFUSE_AGENT_TOKENS=require`, which this stack runs, an agent that acts for a person may send `x-fuse-delegation` and `x-fuse-delegation-dpop` beside its own token; the policy plane is then told the person's chain as proven. A proxy in front of the gateway must forward both. The stack's own agents send neither, so no behaviour here changes.
3. **The Claude Fable 5.2 price row.** Calls to `claude-fable-5-2` were billed at the fallback rate; TokenFuse v1.25.0 prices them at their own row (8 / 40 USD per million tokens).
4. **Going back to 1.10.0 needs nothing special.** Every image above is a pin in the manifests; applying the 1.10.0 manifests puts the old digests back.

## What changed

- **The pins** (#245): every service above moves to the release built on Go 1.27.4 for GO-2026-6859 (a wardryx, heraldyx, idryx, keyryx, scopyx, typryx, costcrew, agent-conform or qryx release each, plus vouchryx v0.8.0 in #244). The gates that name a pin (`console-engines-are-the-stacks.sh`, `tokenfuse-door-origins.sh`, `keyryx-release-pins.sh`, `wardryx-gateway-key-is-pep.sh`, the pin checks of `gates-have-teeth.sh`) read the new ones.
- **The console build** names qryx v1.2.0 by commit (`QRYX_REF` in `console-image.yml`, invariant 68).

## Evidence

- CI on the release head: `gates`, `fast-gates`, the six teeth shards and the console build for amd64 and arm64.
- Every image digest in the table was read from the registry with `docker buildx imagetools inspect` and matches the release's own record; the publishers' provenance was verified with `gh attestation verify`.
