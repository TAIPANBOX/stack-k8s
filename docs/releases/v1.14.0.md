# stack-k8s 1.14.0

A minor release that moves wardryx to v2.8.0 and builds the console from a newer genaryx. wardryx v2.8.0 gives every hold an end: a hold nobody decides is closed as `expired` once it has waited `WARDRYX_HOLD_TTL` (24 hours, the default this release keeps), and the held agent may withdraw its own hold. An admin key cancels nothing. The console this tag publishes shows those two closures as what they are, in a neutral colour, instead of as a refusal.

## Upgrade first

1. **Re-run the launcher, or apply the manifests of this tag.** No new object, no changed claim, no new setting. One image moves by tag and digest:

   | Image | 1.13.0 | 1.14.0 |
   |---|---|---|
   | wardryx (planes, console engine, keyryx patch) | v2.7.0 `91dccc66` | v2.8.0 `f9b86a82` |

   This tag also publishes the console image, `genaryx-console:v1.14.0`, built from genaryx `cb7f779` (was `fb5e036`) with the engines above (tokenfuse v1.25.0, wardryx v2.8.0), and the two tunnel images, `stack-caddy` and `stack-wg`. The manifests of this tag pin the console image they pinned before, `genaryx-console:v1.12.0`; the next release pins the one this tag publishes.
2. **Holds older than 24 hours close at wardryx's first start.** Every pending hold that has already waited the lifetime is closed as `expired`, with no token and one `approval_expired` event each. To keep such holds open longer, set `WARDRYX_HOLD_TTL` (up to `168h`) on the wardryx Deployment before the upgrade, and decide them in that time.
3. **The console pinned here, v1.12.0, shows an expired or withdrawn hold in the refusal colour,** under its raw `decision` value. Nothing is decided wrongly: it reads the row, and every pending hold is decided as before. The next release's console reads them correctly.
4. **Going back to 1.13.0 needs nothing special.** Apply the 1.13.0 manifests. Holds already closed as `expired` or `withdrawn` stay closed under wardryx v2.7.0.

## What changed

- **The pins**: wardryx v2.8.0 in the planes, both Keyryx patches and the console's wardryx engine (`images/console.Dockerfile` and its label, invariant 79). The gates that name the pin (`console-engines-are-the-stacks.sh`, `wardryx-gateway-key-is-pep.sh`, the pin checks of `gates-have-teeth.sh`) read the new one.
- **The console build** names genaryx `cb7f779` by commit (`GENARYX_REF` in `console-image.yml`, invariant 68). Between `fb5e036` and `cb7f779`, genaryx:
  - #159: a hold closed as `expired` reads "Expired, nobody decided in time" and one closed as `withdrawn` reads "Withdrawn by the agent", both neutral, in the inbox history, Agent 360 and the event feed; a value the console does not know reads "Closed (<value>)". What a person can send is still only grant or deny.
  - #160: quinn-udp 0.5.16, for RUSTSEC-2026-0538.
