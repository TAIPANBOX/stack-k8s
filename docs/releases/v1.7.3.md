# stack-k8s 1.7.3

A patch. The images this launcher builds itself move to Go 1.27.3, which fixes [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) in `crypto/x509`, and the console image builds qryx v1.1.1 and mockryx v0.3.1. The manifests of this tag are the manifests of 1.7.2: the console pin follows to the image this tag builds in the next change, because that image's digest exists only after this tag's build.

## Upgrade

1. **Nothing in a cluster changes from this tag alone.** `manifests/` is the same as in 1.7.2, and the console is still pinned at `genaryx-console:v1.7.0` by digest (`sha256:2ceefbba80cf08924d60769ffeec07989e198445af998c3612c1b3e25708b144`). The new images are built by this tag's workflows and are taken up when the pin follows.
2. **Every Dockerfile in `images/` that names a Go version now names 1.27.3** (#210). They are tag pinned (`golang:${GO_VERSION}-alpine`), as before: no digest pin exists for the golang images and none was added.

   | Dockerfile | 1.7.2 | 1.7.3 |
   |---|---|---|
   | `images/console.Dockerfile` (the stage that builds qryx and mockryx) | Go 1.27.2 | Go 1.27.3 |
   | `images/go-service.Dockerfile` (the `BUILD_PLANES=1` build in `build.sh`) | Go 1.27.2 | Go 1.27.3 |
   | `images/scopyx-browser.Dockerfile` | Go 1.27.2 | Go 1.27.3 |
   | `images/wg.Dockerfile` | `golang:1.27.2-alpine` | `golang:1.27.3-alpine` |

   `images/caddy.Dockerfile` builds on the floating `caddy:2-builder-alpine`, which carries no Go pin of its own. It was left alone, so the Go in `stack-caddy` is whatever that base carries when the tag is built, and these notes do not claim 1.27.3 for it.
3. **This tag builds three images.** `console-image.yml` builds `genaryx-console:v1.7.3` for amd64 and arm64, and `tunnel-images.yml` builds `stack-caddy:v1.7.3` and `stack-wg:v1.7.3`. The console is built from the Dockerfile above with Go 1.27.3, and `stack-wg` from `images/wg.Dockerfile`.
4. **The console builds qryx v1.1.1 and mockryx v0.3.1** (#210), up from v1.1.0 and v0.3.0. They are the releases whose images the manifests have pinned since 1.7.1. The two commits in `console-image.yml` are the peeled tag commits, read with `git ls-remote`, and CLAUDE.md invariant 68 names the new tags.
5. **A pull request now builds an image when its Dockerfile changes** (#210). The build-only job ran only when the workflow file changed, so a Dockerfile edit was first built on the tag push. It now also runs on `images/console.Dockerfile`, `images/wg.Dockerfile`, `images/caddy.Dockerfile` and `images/uapi-proxy/**`. Nothing is pushed on a pull request.

## Not in this release

- The console pin to the image this tag builds. Its digest exists only after this tag's image build, so the pin to `genaryx-console:v1.7.3` follows in the next change. Until then a cluster runs the v1.7.0 console, which `images/console.Dockerfile` and `console-image.yml` at the v1.7.0 tag show was built with Go 1.27.2, qryx v1.1.0 and mockryx v0.3.0.

## Repository CI, no effect on a cluster

- **Actions bumped** (#178, `scorecard.yml` only): `ossf/scorecard-action` 2.4.4 to 2.5.0 and `github/codeql-action/upload-sarif` v4.38.3 to v4.39.1, each still pinned by commit.
- **The gates run is faster on an idle runner pool** (#211). The teeth run goes from four shards to six, and kubeconform is restored from a cache keyed by its version and the Go version, then checked against the pin, instead of being compiled in each job. No gate and no teeth case was removed; `teeth (5)` and `teeth (6)` are new checks, and `gates` waits on them.

## Measured

- CI on #210: fast-gates, gates, secretscan and the four teeth shards green, and the build-only jobs green: the console image on amd64 and arm64, and the wg and caddy images on amd64 and arm64. That shows the Dockerfiles build with the new Go and the smoke tests pass, not which Go the pushed images will carry.
- CI on #211: fast-gates, gates, secretscan and all six teeth shards green, and the same on main after the merge (run 40761983366, commit `5df21fb`). On an idle pool, with the same base commit, the run took 4 min 18 s before and 3 min 09 s after.
- Scorecard on main after #178 and #210 green (run 40761983526, commit `5df21fb`).

## Not measured

- Nothing in this release was run on a live cluster. The three images this tag builds do not exist before the tag, so no digest was read, no build provenance was checked for a Go 1.27.3 base, no cosign signature was read, and no image was admitted by policy-controller.
- The Go version inside `stack-caddy:v1.7.3`, for the reason in item 2.
- The six-shard teeth run under a busy runner pool. Each of the two new jobs waits for a runner of its own there, and #211 did not measure that against four shards.
