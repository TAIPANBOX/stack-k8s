# stack-k8s 1.1.32

Pins only: tokenfuse moves to `v1.8.0`.

## What moves

- **tokenfuse `v1.7.0` -> `v1.8.0`**: `tokenfuse-control-plane`, the gateway,
  its `focus-export` sidecar and `tokenfuse-mcp-broker`. The tag is v1.8.0 on
  tokenfuse `8023010`, published 2026-10-08 for amd64 and arm64 (index
  `sha256:61df27faf983c98e216427c67723dd23f88544382867fa2cd38bc444f236d40f`
  for `tokenfuse:v1.8.0`,
  `sha256:a956befcad7f1fbdc1573e47722d25b381f4a134164c3e38da9f826c9a041484`
  for `tokenfuse-control-plane:v1.8.0`, read with
  `docker buildx imagetools inspect`). TokenFuse's own notes:
  `docs/releases/v1.8.0.md` in that repository.
  - **The control plane files a call refused for identity under the
    credential that made it** (tokenfuse#373), as the FOCUS export has since
    v1.7.0, and counts every Breaker reason as compliance evidence.
  - **A refused run reads as refused, and a fallback price is visible**
    (tokenfuse#375), on the control plane's runs and summary.
  - **`GET /v1/price-book` on the gateway** (tokenfuse#374), behind the same
    admin key as the gateway's other observability routes.
  - **A call forwarded under identity warn mode is marked** (tokenfuse#377):
    a trace column, `identity_reason`, and a FOCUS column appended last,
    `x_identity_reason`. These manifests configure no client keys and no
    identity map for the gateway, so no identity check runs here and the
    column stays empty.

No other pin moves. TokenFuse changed no Dockerfile between v1.7.0 and
v1.8.0, so the binary paths and the sidecar's `/bin/sh` stay where the
manifests expect them.

## Upgrading

- **Nothing to configure.** TokenFuse names no new setting, and every
  `TOKENFUSE_*` name these manifests hand the gateway, the control plane or
  the broker is still read at v1.8.0.
- **The `focus-export` sidecar's CSV gains one column at the end**,
  `x_identity_reason`. CostCrew's FOCUS reader reads by name and refuses only
  a missing column.

## Not proven

- **This pin running on a cluster.** `verify.sh` and `security-tests.sh` were
  not run, and no live model call was made.
