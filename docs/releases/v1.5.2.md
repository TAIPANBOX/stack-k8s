# stack-k8s 1.5.2

A patch. The AWS launcher's host key check still refused every node in 1.5.1: the EC2 console text ends every line in CRLF, and the parser read no fingerprint. Nothing else changes: no manifest, no pin, no default, and GCP and bring-your-own servers are not affected.

## Upgrade

Nothing to do on a running cluster. To deploy to AWS, use the 1.5.2 checkout; nodes created by 1.5.0 or 1.5.1 can be deployed by it without a new apply.

## What changed

- **Carriage returns are removed before the console block is read.** `aws ec2 get-console-output --output text` returns a carriage return before every newline. After the syslog prefix (fixed in 1.5.1) is removed, the last field of each fingerprint line ended in `\r`, which the strict line shape refuses, so no line was read and each node was refused as a mismatch. Nothing was connected to. GOTCHAS 148.
- `scripts/hostkeys-are-verified.sh` case D4, with a fixture that carries the prefix and CRLF ends, one scenario and one teeth case.

## Measured

- The console captured from a live m7i.xlarge on 2026-10-19 (702 carriage returns) through the fixed function gives three fingerprints, equal to the node's keyscan.

## Not measured

- A full AWS deploy from the 1.5.2 tag. It is the next step of the live run that found this.
