# stack-k8s 1.1.43

The launcher runs TokenFuse's personal-data scanners in shadow. Before this release
the gateway and the MCP broker started with them off, so nothing looked for personal
data in prompts or tool arguments. Now every gateway and broker start records how many
findings there were and of which kinds, and lets the call through. One switch,
`--pii-mode`, changes the mode. The release also seeds an allow-list rehearsal policy
in Wardryx for the mockryx drill.

## What moves

- **The scanners run in shadow** (`manifests/10-planes.yaml`, the gateway container,
  and `manifests/52-tokenfuse-mcp-broker.yaml`, the broker). `TOKENFUSE_DLP_PII` and
  `TOKENFUSE_MCP_DLP_PII` are set to `shadow` on both. TokenFuse's own default, off, is
  unchanged for every other deployment.
- **The switch, `--pii-mode off|shadow|mask|block`,** on `deploy.sh`,
  `cloud/gcp/deploy-gcp.sh` and `cloud/aws/deploy-aws.sh`, or `PII_MODE` in the
  environment. `pii/mode.sh` refuses any other word before anything is installed. The
  value is applied after the manifests, because `apply -k` puts the declared `shadow`
  back. The broker takes it only when the typed-answer plane is applied, since its
  Deployment exists only then.
- **A seeded allow-list policy** (`manifests/00-base.yaml`, `wardryx-policy`). The
  policy `mockryx-allow-list` targets `agent://mockryx.local/allow-list-rehearsal` and
  allows only `lookup_order_status`. Wardryx `v1.3.0`, the pin this release keeps, reads
  `allow_tool`.

## What shadow records

Shadow never refuses a call and never writes the matched text. It records the count and
the kinds of what it finds, which are `pii_email`, `pii_card` (Luhn-checked) and
`pii_phone` (international form only):

- the gateway notes the count and kinds on the call and forwards the prompt unchanged;
- the broker forwards tool arguments unchanged and logs the count and kinds;
- on a tool response the broker adds a `_tokenfuse` note with the count and kinds, and
  the agent reads that note.

## Upgrading

- **Shadow is a change for every deployment of this release.** Calls behave as before,
  but the gateway and the broker now record counts and kinds of personal data. What lands
  in a record is the count and the kinds, never the text.
- **Back to off:** re-run with `--pii-mode off`. Give the flag on every run. A re-run
  without it returns both to shadow, the same as the firewall flag.
- **To mask or block:** `--pii-mode mask` replaces each finding with `[REDACTED:kind]`
  before the call is forwarded. `--pii-mode block` refuses a call that carries a finding,
  including a false positive, so choose it for a workload that can take that.
- **Rollback trap for the seeded policy.** A Wardryx build older than v1.3.0 refuses a
  policy file that carries `allow_tool` at start, with `field allow_tool not found`. Before
  pinning Wardryx back below v1.3.0, remove `mockryx-allow-list` from the policy file.

## Measured

Read, not run. These are reads of TokenFuse `origin/main` at `33512db`:
`crates/gateway/src/defaults.rs` (`dlp_pii_mode_from`, where unset and unrecognised
values are `off`), the broker's own match in `crates/gateway/src/main.rs` (exact words,
no trimming), and the shadow paths in `crates/gateway/src/proxy.rs` and
`crates/gateway/src/mcpbroker.rs`. At the Wardryx `v1.3.0` tag, `internal/policy/policy.go`
reads `allow_tool`, and the README documents it.

The offline gates ran on this branch, and the teeth harness ran once after the commit.
Nothing was started on a cluster.

## Not proven

- **No live run.** Nothing here started a cluster, and `verify.sh` and
  `security-tests.sh` were not run.
- **Detection on real traffic.** Nothing shows the scanners finding personal data in a
  real prompt, or the false-positive rate on real traffic.
- **The seeded policy on a live Wardryx.** Nothing shows the renamed tool refused by a
  running Wardryx.
- **What a running gateway or broker writes.** Nothing checked the trace or event stream
  of a running gateway or broker for the count and kinds.
- **The switch on a live cluster.** The set-after-apply ordering is checked as text only,
  not as a rollout.
