# stack-k8s 1.1.38

TokenFuse moves to `v1.10.0` and heraldyx to `v0.4.0`: a retained call and a
person's closure of it now reach the event bus and the notifier's mail, and
the MCP broker waits long enough for a policy decision that takes more than
50 ms.

## What moves

- **TokenFuse `v1.9.0` -> `v1.10.0`** (`manifests/10-planes.yaml`: the control
  plane, the gateway and its `focus-export` sidecar;
  `manifests/52-tokenfuse-mcp-broker.yaml`). Release notes:
  [tokenfuse v1.10.0](https://github.com/TAIPANBOX/tokenfuse/releases/tag/v1.10.0).
  - **`call_retained` (medium)** when the gateway retains a call whose outcome
    became unknown, and **`retained_closed` (high)** when a person closes one
    with evidence (D10, agent-passport SPEC 6.2). The gateway here already
    exports events to the bus, so both reach heraldyx and the record with no
    configuration.
  - **The broker's policy deadline defaults to 1000 ms** on the tool path. This
    launcher sets the broker's deadline itself only with the typed risk signal
    (7000 ms), and without it the broker asks no policy plane, so nothing here
    changes behaviour; a bare broker would.
- **heraldyx `v0.3.0` -> `v0.4.0`** (`manifests/45-heraldyx.yaml`). Release
  notes: [heraldyx v0.4.0](https://github.com/TAIPANBOX/heraldyx/releases/tag/v0.4.0).
  - Both new TokenFuse types are described in the mail, and the evidence
    reference a person typed is never mailed (only the reservation id and the
    amounts are).
  - agent-conform's `chain_broken` and `chain_unchained` are described instead
    of the generic wording.

No other pin moves.

## Measured

On Docker Compose, 2026-10-12, with `tokenfuse:v1.10.0`,
`tokenfuse-control-plane:v1.10.0`, `genaryx-console:v1.1.36`,
`heraldyx:v0.4.0` and a stub provider: `evidence/closure-e2e/run.sh`, 44 of
44, twice from empty (`evidence/closure-verified.md`, "The bus and the mail").
The gateway wrote one `call_retained` per retained call and one
`retained_closed` per applied closure, none for a refused or repeated close or
on a restart's replay, and heraldyx mailed a description of each without the
evidence reference. Against `tokenfuse:v1.9.0` the same harness failed the 7
checks on the bus and in the mail.

## Upgrading

- **Nothing to configure.**
- **heraldyx's floor is `high` here**, so `retained_closed` is mailed as it
  happens and `call_retained` (medium) lands in the daily summary. A retained
  call whose provider connection broke also mails `dependency_failed` (high)
  at once. Lower `HERALDYX_MIN_SEVERITY` to `medium` to have every retained
  call mailed as it happens.

## Not proven

- **This exact set on a cluster.** Neither image has been deployed from these
  manifests, and `verify.sh` and `security-tests.sh` were not run.
- **The record plane over these events.** trailryx maps both types on its
  `main` (trailryx#94), but the `trailryx-node` release this stack pins
  predates that mapping, so the record refuses them until trailryx is
  released and pinned.
- **A call retained because the caller left**, rather than because the
  provider's connection broke, was not run.
