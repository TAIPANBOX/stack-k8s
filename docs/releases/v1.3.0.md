# stack-k8s 1.3.0

A minor, not a patch: the default install now refuses a pod in agent-stack whose image is not verified, which every earlier release admitted, and an operator's own agent images must be listed before the deploy.

The default install now admits only verified images into the stack's namespace, the admission policy has one
signer per repository instead of one for every TAIPANBOX repository, and every pod that mounts the bus volume is
found by the gate and checked for its group. No image pin moves. The tag is a separate step, taken after the pull
request is merged.

## Upgrade

Read this before you run the deploy again. Items 1, 2 and 4 need an action; items 3, 5 and 6 change what you expect.

1. **The default install turns admission on for agent-stack.** `deploy.sh` runs `policy/up.sh --enforce` after it
   applies the manifests. From then on an image under `ghcr.io/taipanbox/` is admitted only when its signature
   verifies for its own repository, and an upstream image only when it is pinned by digest and listed. Before you
   run it, check that the nodes reach Sigstore's TUF repository, Fulcio and Rekor. A cluster that cannot reach them
   is expected to refuse every new pod in agent-stack; that refusal was not run here. Running pods are not touched; a pod that is
   created again (a restart, a rollout) is checked again. Run the deploy again; the admission step is repeatable.
2. **A cluster with agent-token pods in agent-stack must list their images before the deploy turns admission on.** An agent's own image is not a TAIPANBOX image, and with admission on every image no policy covers is refused. Before you run the deploy, copy `policy/operator-image-policy.example.yaml` to `policy/operator-image-policy.yaml` and list each agent image there: by digest for an unsigned image, or with the keyless identity or the public key that signs it. The deploy applies that copy in the same step, before the namespace is labelled. The copy is not in git. Running agent pods are not checked; a pod created again is. policy/README.md has the templates.
3. **The cloud deploy scripts do not turn admission on yet.** `cloud/gcp/deploy-gcp.sh` and `cloud/aws/deploy-aws.sh`
   are unchanged here. A cloud cluster is not admitted until `policy/up.sh --enforce` is run on it, which is a
   follow-up, not part of this release.
4. **If you ran `policy/up.sh` from v1.2.0 or earlier, run it again from this release.** The policy it installed,
   `taipanbox-signed`, admits any TAIPANBOX repository's signature for every TAIPANBOX image. This release deletes it
   and applies one policy per repository. Nothing deletes it on its own, because `kubectl apply` does not prune.
5. **New pods that mount `stack-events` must run in group 10001**, through `fsGroup`, `supplementalGroups` or
   `runAsGroup` in the pod-level security context. The gate finds every pod that mounts the claim. Three are named
   exceptions, because they write only their own precreated stream and name no bus reader: costcrew (Deployment),
   costcrew-crew (CronJob) and vouchryx. Existing pods are unchanged.
6. **The image pins are the v1.2.0 pins.** Nothing to do for them.

## Changes, by area

- **Admission, default install.** `deploy.sh` runs `policy/up.sh --enforce` after the apply. `policy/up.sh` takes
  `KUBECTL`, so the node's k3s kubectl can run it. Gate: `scripts/verified-images-are-enforced.sh` checks the order.
- **Admission, operator entries.** `policy/operator-image-policy.example.yaml` is the template for an operator's own agent images, by digest or by a named identity or key. The gate holds the rules: no wildcard name, no digest wildcard under static, no entry for `ghcr.io/taipanbox/`, no subject expression that accepts a stranger's repository.
- **Admission, one signer per repository.** `policy/image-policy.yaml` has fifteen TAIPANBOX policies, each naming one
  repository's image names and its own `release.yml` (stack-k8s's `console-image.yml` and `tunnel-images.yml` for the
  console and the tunnel images). A signature made by one repository's workflow no longer admits another's image name.
  The gate holds a table of image name to repository and workflow, and refuses an image a tracked file names that has
  no row.
- **Bus readers, found not listed.** `scripts/stream-files-are-precreated.sh` finds every pod that mounts the
  `stack-events` claim, instead of a hand-kept list of three readers.

## Not measured

- The keyless and key forms of an operator entry: the gate checks their rules, and the kind run measured the digest form only.
- Admission with Sigstore unreachable from the cluster: the decision is to refuse, and the refusal was not run.
- Admission on a cloud cluster, or on a cluster that already runs the stack with pods that predate the policy.
- The admission run is on kind (Kubernetes v1.37.0) with the v1.2.0 pins, not on a k3s node.
