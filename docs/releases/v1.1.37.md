# stack-k8s 1.1.37

The console moves to `genaryx-console:v1.1.36`, the first that signs in an
operator set while it is already running, with no restart (GOTCHAS 50).

## What moves

- **Console `v1.1.34` -> `v1.1.36`** (`manifests/20-console.yaml`, the
  `quality-drift` CronJob in `manifests/40-routines-and-secrets.yaml`, and
  `security-tests.sh`), built by tag v1.1.36 from genaryx `41972c6`
  (genaryx#106).
  - **An operator set after the console started signs in at the next
    attempt.** The console used to read `operator.json` once, at startup, so
    `genaryx-web set-password` inside a running pod reported success while the
    sign-in page kept saying the box had no operator until the pod was
    restarted. It now reads the file again while it holds no operator.
  - **A password changed on a running console still needs a restart.** An
    operator the console already holds is never read again, as before. The
    deploy scripts keep their restart after set-password for that reason: a
    re-run sets the password the operator typed, and only the restart makes it
    take effect.
  - `set-password` now says this on stderr, and `serve`'s startup warning says
    the next sign-in picks a new account up.

No other pin moves. `v1.1.35` built the same console as `v1.1.34`.

## Measured

On Docker Compose, 2026-10-12, with `tokenfuse:v1.9.0`,
`tokenfuse-control-plane:v1.9.0` and a stub provider, `evidence/closure-e2e/run.sh`
now sets the operator inside the running console and does not restart it
(`evidence/closure-verified.md`):

- **`genaryx-console:v1.1.35`** (genaryx `2317d80`): 16 failed. The running
  console still said it had no operator after `set-password`, and sign-in
  answered 503.
- **`genaryx-console:v1.1.36`** (genaryx `41972c6`): 32 of 32, twice from
  empty: the console said it had an operator without a restart, the operator
  signed in, and every closure check from 1.1.35 passed again.

The image is published for `linux/amd64` and `linux/arm64`
(`docker buildx imagetools inspect`); the runs above were on arm64.

## Upgrading

- **Nothing to configure.** The console's state, its operator account and its
  passkeys carry over; operators sign in again after the rollout, as after any
  console restart.

## Not proven

- **This exact set on a cluster.** The image has not been deployed from these
  manifests, and `verify.sh` and `security-tests.sh` were not run against a
  cluster.
- **A password changed on a running console** is unchanged by this release and
  was not re-measured.
