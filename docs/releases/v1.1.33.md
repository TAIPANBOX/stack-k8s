# stack-k8s 1.1.33

Pins only: costcrew moves to `v0.5.0`.

## What moves

- **costcrew `v0.4.0` -> `v0.5.0`** (opt-in, `manifests/49-costcrew.yaml`): the
  `costcrew` console Deployment and the `costcrew-crew` CronJob, one image for
  both. The tag is costcrew `b487527`, published 2026-10-08 for amd64 and arm64
  (index `sha256:8250a1dc895c750160bba164a32d80e52352516118b0029dd2577bca9f863a40`,
  read with `docker buildx imagetools inspect`). This launcher pins by tag.
  Release notes:
  [costcrew v0.5.0](https://github.com/TAIPANBOX/costcrew/releases/tag/v0.5.0).
  - **AI spend read from TokenFuse is counted once.** Exporting the same trace
    again (as the TokenFuse upgrade in 1.1.32 invites) no longer counts every
    call twice, and a call refused for identity is filed under the credential
    that made it, not the agent it claimed.
  - **Pages that say what is so.** `/ai` labels a credential as a credential
    and counts blocked calls by the gateway's reason; `/engines` and
    `/sprint/plan` show what a model is sent; a refused plan request says
    whether it was paid for; a customer unit's page names the business unit it
    is charged under.
  - **The runner runs one local-engine task at a time by default**
    (`-local-parallel`, default 1). The `costcrew-crew` CronJob passes no
    `-model-url`, so it has no local engine to run and this changes nothing
    here.

No other pin moves. Every flag this manifest passes (`-addr`, `-data`,
`-stack-events`, `-stack-passports`, `-stack-host`, `-stack-owner` on the
console; `-due`, `-data`, `-live`, `-ceiling`, `-stack-events`, `-stack-host`
on the runner) still exists at the tag, the runner still reads
`OPENROUTER_API_KEY` and `ANTHROPIC_API_KEY`, and the image still runs as
65532:65532 with the same five binaries. No console flag was added or removed.

## Upgrading

- **Nothing to configure.** Re-applying the manifests pulls the new image.
- **New columns are added at start** (`ai_calls.key_id`, `block_reason`,
  `call_key`; `connections.last_import`, `last_import_result`;
  `tasks.live_tokens`, `live_token_ceiling`; and, with typryx configured,
  `anomalies.hint_fields_sent`, `hint_held_back`). No data is rewritten. The
  console and the runner open the same store; whichever starts first adds them.
- **If you import TokenFuse exports into the console,** import the gateway
  folder once after upgrading. A store that already holds two exports of the
  same trace counts those calls twice until its next import, which keeps each
  call once.
- **Coming from v0.3.0** (skipping 1.1.30), the v0.4.0 changes in 1.1.30's
  notes apply as well: everybody signs in again once, and the console's files
  become 0600.

## Not proven

- **This exact set on a cluster.** v0.5.0 has not been deployed from these
  manifests, and `verify.sh` and `security-tests.sh` were not run against it.
- **The TokenFuse import through this stack.** No export was imported here.
  CostCrew's own notes say no real TokenFuse 1.7.0 export was read for its
  release; its changes are held by its tests.
