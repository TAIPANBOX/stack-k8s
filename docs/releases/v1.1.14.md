# stack-k8s 1.1.14

This tag publishes a console image whose copilot, Felyx, names itself to the
gateway. Nothing in the pinned set moves: the manifests keep
`genaryx-console:v1.1.1`, which moves only after a run.

## What the tag builds

- **`genaryx-console:v1.1.14`, with genaryx#81.** Felyx's model calls now carry
  `x-fuse-agent-id` beside `x-fuse-run-id`. Measured on 2026-09-27: pointed at
  this stack's own TokenFuse gateway, whose policy hook runs in enforce, Felyx
  was refused `400 identity_required` on its first question, because it sent
  no agent identity; nothing reached the model. The id is
  `GENARYX_COPILOT_AGENT_ID`, or `agent://<GENARYX_ORG_DOMAIN>/genaryx/felyx`
  when that is unset; a malformed value leaves Felyx disabled with the reason,
  and the rest of the console keeps working.

## Not in this release, said plainly

- The manifests do not point Felyx at the stack's gateway and do not set the
  new variable. Out of the box Felyx still defaults to a local Ollama the
  stack does not ship.
- Felyx's residency check accepts only a literal loopback or private address,
  so pointing it at the gateway takes the gateway Service's cluster address,
  not its name.
- The image is published and not yet run on a cluster.
