# stack-k8s 1.1.18

Two things turn on here: Felyx, the console's copilot, is governed like any
agent by default, and a verified delegation plane is one script away.

## Felyx through the stack's own gateway

The console moves to `genaryx-console:v1.1.17` (genaryx#83). Felyx now points
at this stack's gateway by its Service name, `http://tokenfuse-gateway:4100`,
under `agent://<trust domain>/genaryx/felyx`, so every question it answers is
priced, budgeted and policy-checked. Its residency check accepts that one
name, resolved on every connection to cluster addresses only. No key ships:
create the `stack-copilot` Secret and restart the console to turn it on;
without it Felyx says the key is not set and the rest of the console is
unchanged. `55-copilot-cloud.yaml` now only picks a larger model; it no longer
sets `GENARYX_COPILOT_ALLOW_REMOTE`, which went around the gateway. Invariant
25, gated by `scripts/felyx-through-the-gateway.sh`.

Measured on forge (k3d, three nodes), 2026-09-27: with a dummy key Felyx
reported `endpoint http://tokenfuse-gateway:4100, local: true` and its question
came back as the provider's 401 through the gateway (nothing billed); with the
allow-list removed it refused the endpoint; with no Secret it said the key is
not set. verify.sh 16/0/1, security-tests.sh 24/0/3.

## An opt-in delegation plane (#114)

`delegation/up.sh --issuer ... --audience ... --jwks-file ...` brings up
vouchryx (`ghcr.io/taipanbox/vouchryx:v0.1.0`) and turns on the gateway's
delegation door, so an `on_behalf_of` chain is verified rather than trusted
(GOTCHAS 105, now fixed; invariant 24). Off by default. The gateway is given
the JWKS vouchryx itself serves. Keys are minted once into a Secret and reused.
Measured on forge: a delegated call accepted; the subject revoked and the next
call refused `delegation_refused` 1.4 s later at a 1 s poll; the refusal
survived a vouchryx restart; `delegation/down.sh` left the gateway with no
delegation variable. Review found and fixed three defects before release, each
measured red first: the namespace's Pod Security labels were dropped by a bare
Namespace apply (GOTCHAS 114, now gated), the poll interval flag was not
applied, and the gateway's audience refused any `--audience` other than
vouchryx's own address.

## Not in this release, said plainly

- Felyx with a real key through this path was measured on 2026-09-27 before
  this release with the cluster address (N10); after it, only with a dummy key.
- The gateway still forwards a caller's `Authorization` header to the provider,
  which on a delegated call carries the delegation token; tracked separately in
  tokenfuse.
- A real customer IdP behind `delegation/up.sh`; only a throwaway one was used.
