# stack-k8s 1.1.46

This release moves TokenFuse to v1.14.0 on every pin, and carries the two changes merged after the
`v1.1.45` tag: the teeth run split into four CI shards (#172) and the console pin moved to
`v1.1.45` (#173). It is a minor release for the launcher, because the TokenFuse change brings
gateway behaviour an operator should read before a re-apply.

Merging this release changes no running cluster on its own. A deploy that re-applies the manifests
after it moves the gateway, the Cloud control plane and the MCP broker to TokenFuse v1.14.0. The tag
builds the console image `v1.1.46`; the pin to it comes in a separate pull request after the tag, as
`v1.1.45` did, so the console stays at `v1.1.45` in this release.

- `console-image.yml` publishes `ghcr.io/taipanbox/genaryx-console:v1.1.46`, built for amd64 and
  arm64 from the tag's `images/console.Dockerfile`. Its five source repositories are checked out at
  their default-branch head at build time, not at a pinned commit. When this was written they were
  `genaryx` `6a05cbce64b7`, `qryx` `21f17441e363`, `mockryx` `9fa387fe2b5f`, `verdryx`

## Changes, by invariant

**The teeth run is split into four CI shards (invariant 49, #172).** The teeth step was the slowest
step of the gates check (5 min 22 s on the last green `main` run before the change). Its cases are
divided by position between four parallel jobs, and `gates` is still the one required check, now an
aggregate of the fast job and the four shards. `scripts/teeth-shards-cover-every-case.sh` fails
unless the shards together run every case exactly once, and it runs in the fast job and in
`.githooks/pre-push`. The runner now runs from a copy of itself, so a planted fault cannot make a
running shard stop with a syntax error.

**TokenFuse v1.14.0 on every pin.** The release notes of TokenFuse v1.14.0 are the record for the
gateway, and the points an operator meets on a re-apply are these:

- A gateway admits nothing a budget governs until it has read its control plane's money state. A
  budget-governed call that arrives before that is answered `503 seed_pending`, retryable, or marked
  in shadow. A rollout that restarts the gateway can show this for a short window.
- A streamed answer's tool calls are judged as a buffered answer's are, on both wires. A stream whose
  tool call the taint policy denies is cut before the call reaches the agent.
- The trace and the FOCUS export gain nullable columns (`pii_findings`, `x_price_basis`,
  `x_pii_findings`). Old files keep reading.
- A refused client key is recorded on the event bus, and the exit flush delivers what the gateway
  still holds to the Cloud within five seconds on SIGTERM.
- The price book prices `openai/` ids at OpenAI's list rate. A cost that was charged at the fallback
  rate can change.

## What an existing cluster does

- Merging changes no running cluster on its own.
- A re-apply of these manifests rolls the `tokenfuse-cloud` Deployment (image
  `tokenfuse-control-plane`), the `tokenfuse-gateway` Deployment with its `focus-export` sidecar, and
  the MCP broker to v1.14.0. The `seed_pending` window above is the one behaviour a running agent can
  see during that roll.
- The teeth split runs only in CI and in `.githooks/pre-push`. It touches no cluster.

## Measured

- The gates in `.github/workflows/gates.yml`, on the release commit, in CI. The run is linked from
  the pull request.
- The index digests above were read with `docker buildx imagetools inspect` on 2026-10-15.

## Not proven

- The TokenFuse v1.14.0 pins have not been applied to a running cluster from this launcher. The
  `seed_pending` window has not been measured on a cluster built from this release.
- The teeth shards' wall time is read from the CI run of the release commit, not from this text.
- TokenFuse v1.14.0's own not-proven items stand as its notes state them: no live provider call on
  the new images, and the seed gate's restart case was reproduced on one host only.
- The console `v1.1.46` image is built by the tag and is not pinned by this release.
