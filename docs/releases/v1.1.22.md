# stack-k8s 1.1.22

Typed answers now ask where your data goes, and typryx moves to `v0.3.0`.

- `--typed-mode jev|own-model|off` on all three launchers (`deploy.sh`,
  `cloud/gcp/deploy-gcp.sh`, `cloud/aws/deploy-aws.sh`), default `off`;
  `--with-typed` alone renders byte-identical to before (the stub backend).
  `jev` sends the fields a template names to TypeSafe AI's hosted API;
  `own-model` points typryx at your own OpenAI-compatible server. A key becomes
  a Secret mounted read-only as a file, never an environment value or a
  ConfigMap; a missing or blank key file is refused before anything is
  installed. A new NetworkPolicy, `typryx-egress-model`, lets typryx reach only
  what the chosen mode needs (`--typed-model-cidr` for a model server named by
  a LAN host name).
- `manifests/51-typryx.yaml` pins typryx `v0.3.0`.
- `--typed-training` (off by default) keeps typryx's training log at
  `/var/lib/typryx/training` on the existing `typryx-state` claim beside the
  ledger: no new PersistentVolumeClaim.

Measured 2026-09-30, client-side only: every mode, with and without
`--typed-training`, renders and passes kubeconform `--strict`; the key appears
in no rendered manifest. Not run: a pod on a cluster with these manifests, a
live Jev call through them, or a pod writing the training log.
