# stack-k8s 1.13.0

A minor release that turns on the argument preview. The person deciding a held tool call in the console now sees the call's arguments, built by wardryx from the bytes the approval is bound to, with secrets and personal data hidden by fixed rules, and sealed so that only the console can read them. The console moves to `genaryx-console:v1.12.0`, the first image that opens the preview, and every launcher mints the console's preview key once.

## Upgrade first

1. **Re-run the launcher.** It applies the manifests, then mints the preview key when the cluster holds none (`lib/preview-mint.sh`, after the approver key). A plain `kubectl apply -k` does not mint it, and the console then waits for the Secret `console-preview-key`, as it waits for its approver key.

   | Image | 1.12.0 | 1.13.0 |
   |---|---|---|
   | genaryx-console (the console, `verdryx-drift`, `verdryx-slo`) | v1.8.8 `55765e22` | v1.12.0 `32c28d24` |

2. **What the mint does.** The key is X-Wing (ML-KEM-768 with X25519), which openssl does not make, so a one-off pod runs `genaryx-web preview-key` on the console's own image, in `agent-stack`, under the restricted security context, with no service account token and a memory-backed `/work`. The private key is read back with `kubectl exec`, which reaches no container log, and is created as the Secret `console-preview-key`, mounted into the console alone at mode 0440 with the pod's fsGroup. Its public half is the ConfigMap `wardryx-preview-recipient`, which wardryx reads as `WARDRYX_PREVIEW_RECIPIENT`. wardryx is restarted once after the first mint, because it reads that at start. A re-run keeps both; if only one of the two is there, the launcher stops and changes nothing.
3. **What changes for a person approving.** A sealed hold shows "Show arguments", and a grant needs it opened first; a denial does not. A hold with no preview (no arguments, arguments the enforcement point truncated) is granted with "Grant unseen", and the record says so.
4. **Going back to 1.12.0.** Apply the 1.12.0 manifests. They pin console v1.8.8, which cannot decide a hold wardryx sealed, so first delete the ConfigMap `wardryx-preview-recipient` and restart wardryx, and decide or let lapse the holds sealed before that. The Secret can stay; nothing else reads it.

## What changed

- **The preview key** (invariant 91): `lib/preview-mint.sh`, called by `deploy.sh` and both cloud launchers after their last `apply -k`; the console's `GENARYX_PREVIEW_KEY_FILE` and its read-only mount; wardryx's optional `WARDRYX_PREVIEW_RECIPIENT`. Held by `scripts/preview-key-is-minted.sh`, its static half reading the library, the three launchers and both manifests, its behavioural half running the mint against a stub kubectl over six starting states, with fourteen teeth cases and `features/the-preview-key-is-minted-once.feature`. `verified-images-are-enforced.sh` lists the mint pod's image, read from the console's own Deployment, with its reason.
- **The console pin** moves to v1.12.0 in the console, the two quality CronJobs and the security tests.

## Evidence

- CI on the release head: `gates`, `fast-gates` and the six teeth shards.
- The console digest was read from the registry with `docker buildx imagetools inspect`, and its provenance was verified with `gh attestation verify -R TAIPANBOX/stack-k8s`.
