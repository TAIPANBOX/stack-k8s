# stack-k8s 1.1.5

The money plane at 1.0.2, the gateway, its `focus-export` sidecar and the
control plane (tokenfuse `docs/releases/v1.0.2.md`): a subject revocation
now matches an agent anywhere in a token's chain, not only the human at its
root; a revocation snapshot with no `revocations` array is a failed poll,
never an installed empty list; and a child run's parent is checked against
the chain the ledger actually admitted it under, so a parent that shows up
between reserve and settle no longer loses another call's reservation.
Nothing else in the pinned set moves. `@decided 2026-09-14`: a launcher pin
of a patch release moves without a cluster run when the release changes
what the gateway settles or writes, not how it starts or answers. All three
corrections hold to that reasoning: `compat/1.0.json` names no changed
route, default or wire body, and each fix is a check or an accounting rule
inside the running gateway rather than a change to how it starts or what it
answers on the wire; the tokenfuse tests, mutants and a second model's
review of the diff stand for them (estate-gates `PROVEN.md`), and the 1.1.0
cluster run stands for the rest of the set.

## The pinned set, 2026-09-18

As in 1.1.4, with `tokenfuse:v1.0.2` (twice) and
`tokenfuse-control-plane:v1.0.2` in place of v1.0.1.

## What to know on the way in

- An orchestrator whose workers call first: in enforce mode, a worker naming
  a parent run this gateway has not opened is refused, until the coordinator
  makes its own first call or an operator sets a Cloud budget for that
  parent id.
- A run keeps the parent it was opened with. A later call that names a
  different parent, or names one after the run has already reserved, is a
  400, not a money refusal.
- A `TOKENFUSE_DELEGATION_REVOCATIONS` feed that answers a body with no
  `revocations` array now fails the first fetch at startup, or is a logged
  failed poll afterwards, never an installed empty list.

## Not in this release, said plainly

- No cluster run on this set, and `verify.sh`'s bus-line check (1.1.2) is
  still unseen on a live cluster; the next run is where all of it is first
  seen.
- tokenfuse's own "not proven" list stands here too: restart durability, the
  raft backend's parity with the in-process ledger, and a reservation held
  across a call cancelled before the provider answers. HA is compiled out
  of every shipped image, so the raft item does not apply to this manifest
  set either way.
