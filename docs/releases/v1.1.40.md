# stack-k8s 1.1.40

TokenFuse moves to `v1.11.0`. The gateway and the MCP broker now read what a
tool says about itself, not only what it is called. On this launcher that
reading is logged or recorded, not acted on; see "What this launcher sets".

## What moves

- **TokenFuse `v1.10.0` -> `v1.11.0`** (`manifests/10-planes.yaml`: the control
  plane, the gateway and its `focus-export` sidecar;
  `manifests/52-tokenfuse-mcp-broker.yaml`). Release notes:
  [tokenfuse v1.11.0](https://github.com/TAIPANBOX/tokenfuse/releases/tag/v1.11.0).
  Index digests, read with `docker buildx imagetools inspect`:
  `tokenfuse:v1.11.0` `sha256:ce983204dcb603bead1d45b56ed2f6aee5e1db02416757c3f60f100eaa7fc605`,
  `tokenfuse-control-plane:v1.11.0` `sha256:6e074b57d0b34e749246e72fb5159dd27fbfc650aa30ed5127f8af82bbb69ee1`.
  - **The scan reads tool metadata** (TokenFuse invariant 92). `mcp-scan` and
    the live broker look for a credential, an order to run another tool, a
    local credential path, text addressed to the model and hidden text, in a
    tool's description and in its parameter descriptions. They matched stock
    phrases only before.
  - **A drifted tool cannot be called** (TokenFuse invariant 91). With the
    broker's scan in `block` and a lock file configured, a `tools/call` for a
    tool whose definition changed since the lock pinned it is refused
    (JSON-RPC `-32003`, decision `refused-tool-changed`).
  - **Declared tools are read** (TokenFuse invariant 93). With the gateway
    firewall in `shadow` or `enforce`, the tools a request declares are
    scanned. A high or critical finding labels the run `suspected_injection`.
    The request itself is never refused for a description.
  - **quinn-proto `0.11.15` -> `0.11.19`** (RUSTSEC-2026-0338 to 0342), inside
    the TokenFuse binary. This repository carries no lockfile for it.
- No other pin moves.

## What this launcher sets

Read from the manifests and the deploy scripts, not from the release notes:

- **Gateway firewall: not set.** `TOKENFUSE_FIREWALL` is absent, so the
  built-in `shadow` mode applies. In shadow a poisoned declaration is recorded
  (the run is labelled `suspected_injection`, one `taint_raised` event is
  written) and not acted on. Nothing in this stack denies a run for it.
- **Broker scan: not set.** `TOKENFUSE_MCP_SCAN` is absent, so the broker runs
  in `warn`: a finding is logged and the listing or call is forwarded.
- **Broker lock: not set.** `TOKENFUSE_MCP_LOCK` is absent, so no tool
  definition is pinned. The drift check (invariant 91) runs only when a lock is
  loaded, so it cannot fire on this launcher in any scan mode.

What that means here: invariant 91 is inactive. Invariant 92 runs in `warn`, so
a finding is logged and the listing is forwarded. Invariant 93 records in
`shadow` and does not act.

The broker exists only on stacks whose typed-answer mode is not `off`: that is
`--with-typed` (the stub backend), or a `--typed-mode` other than `off`. A stack
with the typed mode off has no broker, so the broker statements above do not
apply to it.

## Upgrading

- **Nothing to configure.** TokenFuse renames no environment variable and adds
  none, so nothing in these manifests changes.
- **A consumer of the broker's `tool_call` records** sees one new `decision`
  word, `refused-tool-changed`. This launcher writes it only if a lock is
  configured, which it is not.

## Not proven

- **This exact set on a cluster.** Neither image has been deployed from these
  manifests, and `verify.sh` and `security-tests.sh` were not run.
- **Invariant 91 on this launcher.** It is not active here (no lock, scan in
  `warn`), so no refusal of a drifted tool has been observed on this stack.
- **Drift state lives in the broker process.** A restart forgets which tools
  drifted. A change no client re-listed is not seen. Added and removed tools
  are not acted on (TokenFuse's notes).
- **Declared tools are not pinned across turns.** A `taint_raised` record names
  the stage `tool_result` for text that is not a tool result (TokenFuse's notes).
- **Shapes, not meaning.** A description that asks the model, in calm prose, to
  invent an answer carries no shape and passes.
- **No live gateway, broker or real provider** was run with TokenFuse v1.11.0.
  Every change was measured by its tests through CI (TokenFuse's notes).
