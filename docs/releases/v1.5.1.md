# stack-k8s 1.5.1

A patch. It fixes the AWS launcher's host key check, which refused every node of a fresh cluster before connecting to any, so `cloud/aws/deploy-aws.sh` from 1.5.0 could not deploy. Nothing else changes: no manifest, no pin, no default.

## Upgrade

Nothing to do on a running cluster. To deploy to AWS, use the 1.5.1 checkout. GCP and bring-your-own servers were not affected.

## What changed

- **The EC2 console block is read as EC2 prints it.** On EC2, cloud-init writes the host key fingerprints through syslog, so every line of the block carries a prefix such as `<14>Oct 19 17:25:04 cloud-init: `. The 1.5.0 parser read the second field of each line as the fingerprint, which on that shape is the month, so it read none and refused each node as a mismatch. Nothing was connected to and nothing was written, which is the safe outcome, and it stopped the deploy. The parser now removes that prefix only in its exact shape and only when the program is cloud-init, then reads a line only when it is exactly `<bits> SHA256:<base64> <comment> (<TYPE>)`. A fingerprint printed under another program's prefix is not read. GOTCHAS 145.
- `scripts/hostkeys-are-verified.sh` gains cases D2 (the live shape is read) and D3 (another program's line is not), two scenarios in `features/hostkeys-are-verified.feature`, and two teeth cases.

## Measured

- The live console block and a keyscan of the same node, 2026-10-19, 3 x m7i.xlarge in eu-central-1: the three console fingerprints equal the keyscan's three.
- D2 is red on the 1.5.0 parser (refused, exit 2) and green on this one.

## Not measured

- A full AWS deploy from 1.5.1. It is the next step of the live run that found this.
