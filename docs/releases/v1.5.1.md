# stack-k8s 1.5.1

A patch. It fixes the host key check of both cloud launchers, which refused every node of a fresh cluster before connecting to any, so neither `cloud/aws/deploy-aws.sh` nor `cloud/gcp/deploy-gcp.sh` from 1.5.0 could deploy. Nothing else changes: no manifest, no pin, no cluster default.

## Upgrade

Nothing to do on a running cluster. To deploy to AWS or GCP, use the 1.5.1 checkout. On GCP the nodes must be created from it: guest attributes are read at boot, and turning them on for a running node did not publish its keys. Bring-your-own servers were not affected.

## What changed

- **The EC2 console block is read as EC2 prints it.** On EC2, cloud-init writes the host key fingerprints through syslog, so every line of the block carries a prefix such as `<14>Oct 19 17:25:04 cloud-init: `. The 1.5.0 parser read the second field of each line as the fingerprint, which on that shape is the month, so it read none and refused each node as a mismatch. Nothing was connected to and nothing was written, which is the safe outcome, and it stopped the deploy. The parser now removes that prefix only in its exact shape and only when the program is cloud-init, then reads a line only when it is exactly `<bits> SHA256:<base64> <comment> (<TYPE>)`. A fingerprint printed under another program's prefix is not read. GOTCHAS 145.
- **GCE nodes publish their host keys.** The guest agent writes the `hostkeys/` guest attribute only when the instance metadata has `enable-guest-attributes = "TRUE"`, and `cloud/gcp/main.tf` never set it, so the attribute was absent (HTTP 404) and every node was refused at the deadline. It is set now. GOTCHAS 146.
- **The GCE keys are read in the shape gcloud prints them.** `gcloud ... get-guest-attributes --format=json` lists each attribute as `{"namespace": "hostkeys", "key": "ssh-ed25519", "value": "<base64>"}`, the type as the key and the base64 as the value. The 1.5.0 parser matched only whole `type base64` lines and found none. It now reads such an object when its key is a known SSH key type and its value is base64 only. GOTCHAS 147.
- `scripts/hostkeys-are-verified.sh` gains cases D2 (the live shape is read) and D3 (another program's line is not) N (every GCE instance turns guest attributes on) and E2 (the gcloud json shape), four scenarios in `features/hostkeys-are-verified.feature`, and four teeth cases.

## Measured

- The live console block and a keyscan of the same node, 2026-10-19, 3 x m7i.xlarge in eu-central-1: the three console fingerprints equal the keyscan's three.
- D2 is red on the 1.5.0 parser (refused, exit 2) and green on this one.
- GCE, 2026-10-19, 3 x e2-standard-4 in europe-west3-a: without the metadata key `get-guest-attributes --query-path=hostkeys/` answered 404; nodes created with it published ecdsa, ed25519 and rsa keys about 30 s after boot, and with the json fix a deploy passed the host key step on all three nodes (nine key lines).

## Not measured

- A full AWS or GCP deploy from the 1.5.1 tag. Both are the next step of the live run that found these.
