# stack-k8s 1.12.0

A minor release that moves wardryx to v2.7.0 and builds the console from a newer genaryx. wardryx v2.7.0 can show the person deciding a held tool call what its arguments are, sealed so only the console reads them, and the console this tag publishes can open that preview. This tag does not turn the preview on: wardryx runs without `WARDRYX_PREVIEW_RECIPIENT`, so it decides and records exactly as v2.6.2 did. No manifest changes shape and nothing needs a migration.

## Upgrade first

1. **Re-run the launcher, or apply the manifests of this tag.** No new object, no changed claim, no new setting. One image moves by tag and digest:

   | Image | 1.11.0 | 1.12.0 |
   |---|---|---|
   | wardryx (planes, console engine, keyryx patch) | v2.6.2 `b799701c` | v2.7.0 `91dccc66` |

   With a database, wardryx v2.7.0 creates one new table, `approval_previews`, at start. It stays empty while no preview key is set.

   This tag also publishes the console image, `genaryx-console:v1.12.0`, built from genaryx `fb5e036` (was `fd0710e`) with the engines above (tokenfuse v1.25.0, wardryx v2.7.0), and the two tunnel images, `stack-caddy` and `stack-wg`. The manifests of this tag pin the console image they pinned before, `genaryx-console:v1.8.8`.
2. **The preview stays off in this tag, on purpose.** With the recipient set, wardryx refuses a decision on a sealed hold from a console that does not send the new approver statement, and v1.8.8 does not send it. The next release pins the console this tag publishes and mints the preview key, the console's Secret and the recipient wardryx reads, in that order.
3. **Going back to 1.11.0 needs nothing special.** Apply the 1.11.0 manifests. The `approval_previews` table can stay: wardryx v2.6.2 does not read it, and it is empty.

## What changed

- **The pins** (#247): wardryx v2.7.0 in the planes, both Keyryx patches and the console's wardryx engine (`images/console.Dockerfile` and its label, invariant 79). The gates that name the pin (`console-engines-are-the-stacks.sh`, `wardryx-gateway-key-is-pep.sh`, the pin checks of `gates-have-teeth.sh`) read the new one.
- **The console build** names genaryx `fb5e036` by commit (`GENARYX_REF` in `console-image.yml`, invariant 68). Between `fd0710e` and `fb5e036`, genaryx:
  - #158: the approver reads a held call's arguments before deciding. The console fetches wardryx's sealed preview, opens it with its preview key, and shows it as text under a label saying it is data from the agent. A grant of a sealed hold names the preview the person opened.
  - #157: a granted token is brought into view, and leaving the page asks first.
  - #156: rusqlite 0.41.1 with bundled SQLite 3.54.0, for RUSTSEC-2026-0459.
  - #153, #154, #155: CI actions, vitest and vite move to newer versions.

## Evidence

- CI on #247: `gates`, `fast-gates`, the six teeth shards and the console build for amd64 and arm64.
- The wardryx digest was read from the registry with `docker buildx imagetools inspect`, and its provenance was verified with `gh attestation verify -R TAIPANBOX/wardryx`.
