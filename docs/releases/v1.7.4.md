# stack-k8s 1.7.4

A patch that moves three images by tag and digest: TokenFuse from 1.20.1 to 1.20.3 (the gateway, the MCP broker, the `focus-export` sidecar and the control plane), agent-conform from 2.0.1 to 2.0.2 (agent-stack-go v2.0.2), and the console from 1.7.0 to the image this repository's v1.7.3 tag builds. The agent-conform and console images are built with Go 1.27.3, which fixes [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) in `crypto/x509`. The manifests of this tag are the manifests of 1.7.3 apart from these pins.

## Upgrade

1. **Re-run the launcher, or apply the manifests of this tag.** Each image moves by tag and index digest:

   | Image | 1.7.3 | 1.7.4 |
   |---|---|---|
   | tokenfuse (gateway, MCP broker, `focus-export` sidecar) | v1.20.1 | v1.20.3 |
   | tokenfuse-control-plane | v1.20.1 | v1.20.3 |
   | agent-conform | v2.0.1 | v2.0.2 |
   | genaryx-console | v1.7.0 | v1.7.3 |

   The gateway image is `sha256:2b82c87733a8165922f8f6c737a1d19bc0e0156335e88db6c190b17cc2a4a484`, the control plane `sha256:64b9476edeced2c4436d4a5f5bfcbb78b0217f1d85c75af4ec045e21475fe07e`, the agent-conform `sha256:65c0c1ef78effe96f09c5684a203616fed396375e182bedb142a5beaa178b713` and the console `sha256:0db4758c9f3dd2231184063af4f80bce491480f6d7238c02bcbac83abb8d708a`. Each is an amd64 and arm64 manifest list with a legacy `.sig` tag on ghcr.io, the format the policy controller reads. The door origins of invariant 74 do not change.
2. **TokenFuse prices `gpt-6.1-terra` at its own row (from 1.20.2, included in 1.20.3).** Until now a call to that model had no row, so each call was estimated, reserved against the budget and recorded at the fallback price of 15 and 75 USD per million tokens. The model now has the vendor's standard list price. A cluster that routes calls to it will see lower reserved and recorded amounts from the first call on the new image.
3. **TokenFuse carries two zstd advisories as a temporary accepted risk (from 1.20.2, included in 1.20.3).** RUSTSEC-2026-0391 and RUSTSEC-2026-0403 cannot be fixed yet, because the fixed versions need parquet and arrow-ipc 60, which the newest DataFusion release does not allow. TokenFuse records them with an expiry, and its audit gate fails as soon as a fixed version becomes reachable, so the exception cannot outlive the fix. RUSTSEC-2026-0410 is cleared by a newer `zstd-sys`.
4. **TokenFuse 1.20.3 reports refused client keys on the bus in require mode.** With `TOKENFUSE_AGENT_TOKENS=require`, a call with an unknown client key or with no key is still refused with the same `401` and the same bytes. It now also writes an `identity_mismatch` event (severity high) with a fingerprint of the key, never the key itself. If you alert on high `identity_mismatch` events, expect them from require-mode gateways where there were none. No configuration change and no migration; change the image tag.
5. **agent-conform v2.0.2 is built with Go 1.27.3.** The image is agent-stack-go v2.0.2, built with Go 1.27.3 for the same GO-2026-6809 fix. The 2.0.1 image was built with Go 1.27.2.
6. **The console image is the one this tag builds.** `console-image.yml` builds genaryx-console v1.7.3 for amd64 and arm64 with Go 1.27.3, qryx v1.1.1 and mockryx v0.3.1. The 1.7.0 image was built with Go 1.27.2, qryx v1.1.0 and mockryx v0.3.0.

## Not in this release

- The `tokenfuse-dashboard` image is not run by any manifest in this repository, so it is not pinned and does not move.

## Measured

- Each of the four digests (TokenFuse gateway, TokenFuse control plane, agent-conform, console) was read from ghcr.io with `docker buildx imagetools inspect` on 2026-10-28, and each has its `.sig` tag (`sha256-<digest>.sig`), read the same way.
- `scripts/tokenfuse-door-origins.sh`, `scripts/pinned-images.sh`, `scripts/verified-images-are-enforced.sh` and `scripts/chain-verifier-watches-the-bus.sh` pass locally on this branch.

## Not measured

- The TokenFuse 1.20.3 change, the refused-key event on the bus, has not been run on a live gateway in require mode. Its checks are in the TokenFuse repository, not measured here.
- Nothing in this release was run on a live cluster. No image was admitted by the policy controller, and no pod ran the new images.
- The Go version of the console image comes from the Dockerfile at the v1.7.3 tag, not from the image's build provenance.
