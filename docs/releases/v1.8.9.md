# stack-k8s 1.8.9

A patch release. The console can turn a held tool call into a standing grant from its approvals inbox, wardryx 2.6.1 puts on the shared bus only the types the event registry lists for it, and Keyryx custody moves to v0.1.4.

v1.8.8 is the tag that built the console this release pins and has no notes of its own: a signature is accepted only from a tag, so the image a release pins comes from the tag before it.

## Upgrade first

1. **Re-run the launcher, or apply the manifests of this tag.** Three images move by tag and digest:

   | Image | 1.8.7 | 1.8.9 |
   |---|---|---|
   | genaryx-console (the console, `quality-drift`, `verdryx-slo`) | v1.8.6 | v1.8.8 |
   | wardryx (and the console's wardryx engine) | v2.6.0 | v2.6.1 |
   | keyryx (custody and the witness, when Keyryx is on) | v0.1.3 | v0.1.4 |

2. **wardryx decides as it did, and two facts leave the bus.** 2.6.0 wrote `policy_loaded` and `approval_queue_full` onto the shared bus under `source: wardryx`, and the registry lists neither for it. 2.6.1 writes each as a line of its own log instead: `wardryx: policy set loaded ... no_grant_floors=[...]` at each start, and `wardryx: an agent reached its pending cap ...` once per agent. A hold past the cap is still recorded as `approval_requested` with `queue_full: true`. A reader of the bus that counted either type sees none from now on. No schema step, and a rollback to 2.6.0 writes both again.

3. **`./tool-hold/agents.sh agent-list` reads what wardryx loaded from its log.** It read `policy_loaded` off the bus; it now reads the last start line with `kubectl logs deploy/wardryx`, so the account it runs under needs `get` on `pods/log` in `agent-stack`, which a cluster admin's kubeconfig has. A `policy_loaded` record 2.6.0 left on the bus names an older start, and nothing reads it.

4. **Keyryx custody behaves as it did.** v0.1.4 changes only delegated keys: at the bound of four live keys a new key retires its owner's oldest. The policy here holds no delegated key.

## What changed

- **Always allow, from the approvals inbox** (genaryx#152). A tool call held because nothing grants the tool gets "Always allow" beside Grant and Deny. It writes the policy `./tool-hold/agents.sh agent-allow` writes, through `PUT /v1/policies`, adding to what the agent already holds, so `agent-deny` takes it back. It takes the `admin` role and the passkey ceremony a grant has, bound to that hold's id. An agent id with no trust domain gets no button and a line saying why. A hold that came with a static key is granted one. The call on the row still waits for its own answer, and the agent's next call passes. The console journals each attempt as `console.grant_tool`.
- **The console's wardryx engine is 2.6.1,** the stack's own, digest for digest (invariant 79), so a proof replays decisions with the engine that takes them.
- **wardryx v2.6.1** (wardryx#139): only the types SPEC 6.2 lists for wardryx reach the bus, held by a gate in that repository.
- **keyryx v0.1.4** (keyryx#27): at the bound a new delegated key retires its owner's oldest once the next key has signed for the overlap.
