# stack-k8s 1.1.0

Deployment three of three of the TAIPANBOX stack: kustomize manifests, the
images this repository composes, and the bring-up for Hetzner, AWS and GCP.
A stack release is a pinned set with a date: this one moves the money plane to
its 1.0 and the console composition to the `v1.0.0` this repository's own tag
built on 2026-09-13, after a run on 2026-09-14 proved both. It also carries
the GCP preflight fix (#80: `preflight.sh` keeps the operator's
`terraform.tfvars`; issue #79) and the gate that holds it.

## Upgrade note, 1.0.0 to 1.1.0

`kubectl apply -k manifests/` on a running cluster rolls the five workloads
whose image moved (gateway, control plane, console, the two CronJobs' next
runs); volumes, the policy store and the bus stay. The money plane's upgrade
note (tokenfuse `docs/releases/v1.0.0.md`): nothing to migrate, no name,
default or wire body changed after 0.5.1. On GCP, run `preflight.sh` from this
release before the next `terraform apply`: it no longer rewrites the machine
type, disk size or region you chose.

## Not in this release, said plainly

  1.0.0 alike: the console's bus reader stops at the first directory in the
  events volume it cannot open, and the RWX volume has two (`lost+found`, the
  filesystem's own, and wardryx's policy archive). genaryx#71. Invisible to
  `verify.sh`, which asks the console to reach the planes, not to read the bus.
- scopyx on Kubernetes (47/48) was not applied in the run; AWS was not run
  (one cloud, one cluster); RUN-8 load, FAIL-4 and UPG-2 were not re-run (the
  policy plane is unchanged since 1.0.2).
- This tag builds and publishes `genaryx-console:v1.1.0`, `stack-caddy:v1.1.0`
  and `stack-wg:v1.1.0` from the five repositories' main today, as every tag
  here does; the manifests keep pinning `genaryx-console:v1.0.0`, the
  composition this run proved, until a run proves the next one.
