# stack-k8s 1.1.16

TokenFuse moves to 1.4.0 and the policy plane to 1.1.1, both carrying fixes
found on this stack's own lab cluster, and `security-tests.sh` no longer leaves
a pod behind that `verify.sh` counts as a failure.

## What changed

- **`tokenfuse:v1.4.0` and `tokenfuse-control-plane:v1.4.0`** (were v1.3.0), for
  the gateway, `focus-export`, the MCP broker and the control plane. A call's
  cost now rounds once, on the sum, toward over-charging (it rounded each part
  down); a refused delegation proof answers `401 delegation_refused` instead of
  asking for a client key, and the gateway's log names the cause; a delegation
  proof on the OpenAI door is checked against that door's own path.
- **`wardryx:v1.1.1`** (was v1.1.0). A policy that sets `deny_above_usd` or
  `require_human_above_usd` to `0` now means it: every priced call is denied or
  held. Before, a zero was read as "no rule". Existing policies keep their
  `PolicyVersion`.
- **`security-tests.sh` waits for its probe pods to be gone** before it
  reports (GOTCHAS 112), so a `verify.sh` run straight after it no longer fails
  on a pod the test itself left terminating.

## Measured

On 2026-09-27, on a three-node cluster (k3d, 1 server and 2 agents, k3s
v1.36.2, Calico) with this release's manifests applied over 1.1.15:
security-tests.sh 24 passed, 0 failed, 3 noted, and verify.sh started the
moment it returned 16 passed, 0 failed, 1 noted (the same order had failed one
check twice the same day before the fix). With wardryx 1.1.1, a policy of
`deny_above_usd: 0` written through the API came back with the field present
and the gateway refused that agent's next call `403` before the provider.

## Upgrade

`kubectl apply -k manifests` rolls the gateway, the control plane, wardryx and
the console once. A client that matched a delegation refusal on
`type: unauthorized` should match `delegation_refused`.

## Not in this release, said plainly

- The rounding and delegation fixes were proven by tests and mutants in
  TokenFuse; this cluster run exercised the images, not those two paths again.
- The run was on k3d with a host directory standing in for the RWX volume, not
  on Longhorn.
