# stack-k8s 1.19.0

A minor release. Keyryx moves to v0.2.0: rotating or revoking a key is a command on custody's admin socket, and every change is announced on the bus, in custody's own stream, which heraldyx reads. The console image is now genaryx's own release, `ghcr.io/taipanbox/genaryx:v0.1.0`, and this repository no longer builds one. vouchryx moves to v0.9.0 and heraldyx to v0.10.0.

## Upgrade first

1. **Re-run the launcher.** It runs the bus-owner Job again (deleting the finished one first, as since 1.18.0), which now also makes `custody/` beside the bus (owner 20000, group 20101, mode 0771). Keyryx custody waits for that directory before it starts. Applying the manifests by hand: `kubectl -n agent-stack delete job bus-owner --ignore-not-found` before `kubectl apply -k manifests/`, then `keyryx/up.sh`.
2. **Keyryx v0.2.0 has no network admin key.** Custody refuses to start when `KEYRYX_ADMIN_KEYS` is set to anything, and requires `KEYRYX_EVENTS`, which the manifest sets. Rotation and revocation run inside custody's container, as custody's own uid:

   ```bash
   kubectl -n agent-stack exec deploy/keyryx-custody -c keyryx -- keyryx admin rotate wardryx-approval
   kubectl -n agent-stack exec deploy/keyryx-custody -c keyryx -- keyryx admin revoke <kid>
   ```

   Each change lands in `keyryx-custody.ndjson` as `key_rotated` (info) or `key_revoked` (high). heraldyx mails the revocation; a rotation is below its `high` floor.
3. **The console image changes name.** Every console reference (the console Deployment, the verdryx-slo sidecar, the quality-drift CronJob and the probes of `security-tests.sh`) is `ghcr.io/taipanbox/genaryx:v0.1.0@sha256:4030bc81...`, signed by genaryx's `release.yml` on its tag. The Deployment, Service and labels keep the name `genaryx-console`, so load balancers and patches are unchanged. The admission policy admits `ghcr.io/taipanbox/genaryx` on genaryx's own identity. On a cluster that already enforces admission, the launchers now bring this release's policies in before the manifests (`policy/refresh.sh`), so the renamed image is admitted by the apply that names it; `policy/up.sh` then removes `taipanbox-console`, after the rollout, and `genaryx-console` is no longer admitted. Applying by hand on such a cluster: `kubectl apply -f policy/image-policy.yaml` before `kubectl apply -k manifests/`.
4. **No console is built here any more.** `.github/workflows/console-image.yml` and `images/console.Dockerfile` are removed; `deploy.sh` and `build.sh` no longer clone or build the console, and the GCP and AWS deploy scripts no longer take `--console-token`, which only cloned the console. `deploy.sh --console-ref` is gone for the same reason; `deploy.sh --console-token` stays, as the bearer for a private fork's tree with `INSTALL_FROM_MAIN=1`.
5. **vouchryx v0.9.0** refuses an actor credential that is not bound to a key on a first hop. Nothing in this stack sends one: its agents use vouchryx's own `client_credentials` token, which is always bound.
6. **Going back to 1.18.1** means running keyryx v0.1.5 again, which reads `KEYRYX_ADMIN_KEYS` and does not write the stream; `custody/` stays on the claim and is harmless.

## What changed

- **Keyryx v0.2.0** (`ead031a1`), custody and the witness, by tag and digest. keyryx writes its announcements only into a file its own uid owns, and every file in the bus belongs to the bus owner, so the stream sits in `custody/` beside it: custody mounts it at `/var/lib/stack/events` (the same `KEYRYX_EVENTS` path as stack-single), runs in the bus group, and its init makes the file 0640; heraldyx reads it through `keyryx/heraldyx-findings-patch.yaml`, read only, and is its one reader: beside the bus, the stream is outside what the witness, the chain verifier and the record seal read. The patch carries heraldyx's pin, so a run that does not apply heraldyx cannot leave an older one reading a stem it drops. Custody's `KEYRYX_STATEMENTS_DIR` and heraldyx's checkpoint gate are not set: no plane here writes signed checkpoints yet. Invariant 97 and `scripts/keyryx-custody-announces.sh`, with teeth and `features/keyryx-custody-announces-into-its-own-stream.feature`; invariants 30, 56, 59, 72 and 89 and their gates take custody's directory; GOTCHAS 168.
- **The console from genaryx** (invariant 79): `images/console-engines.json` records the engines the pinned image carries, as its labels say, and `scripts/console-engines-are-the-stacks.sh` holds them to the planes the manifests run and, live, to the image's own labels. wardryx is v2.8.0 in both; tokenfuse is v1.25.0 in the console and v1.27.0 in the gateway, a lag recorded with its reason (genaryx-console v1.14.0, pinned before, had the same one), which a genaryx release built with tokenfuse v1.27.0 closes.
- **Invariant 93 retired** with the build: genaryx's own `Dockerfile` installs the web assets from its lockfile with a pinned pnpm. **Invariant 68** keeps its rule with no cross-repository checkout left; its gate now counts every checkout step.
- **Admission across a rename** (invariant 58): `policy/refresh.sh` applies this tree's policies before each launcher's apply where a controller already runs, and `policy/up.sh` removes `taipanbox-console`; `scripts/verified-images-are-enforced.sh` holds both, with teeth.
- **vouchryx v0.9.0** (`341cc2c5`) and **heraldyx v0.10.0** (`7baa8cdb`), by tag and digest.

## Measured

`evidence/keyryx-custody-k3s/run.sh` on k3s v1.36.2+k3s1 in a throwaway VM on the build machine, and Longhorn v1.7.2 RWX, with this tree's manifests under Pod Security `restricted`, the second run over one cluster: 23 of 23, `evidence/keyryx-custody-k3s/output.txt`. The bus owner made `custody/` three times without a change; custody v0.2.0 started and announced to its file; `kubectl exec ... keyryx admin rotate` and `revoke` wrote `key_rotated` and `key_revoked`; a reader shaped as heraldyx's patch read both and could not write, another plane's identity could not append, add or rename in `custody/`; heraldyx v0.10.0 wrote the mail for the revocation; custody kept its file across a restart; the genaryx v0.1.0 image ran verdryx, both engines and `genaryx-web preview-key` as the verdryx-slo sidecar runs.
