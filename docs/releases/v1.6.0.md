# stack-k8s 1.6.0

A minor. It carries the fixes from the live runs of 2026-10-19 and installs keyryx by default, so the record is sealed through key custody and read by an independent witness on every cluster. The tag push also builds the console image from genaryx 03c6c88 (the passkey required by default) and from pinned commits of its other sources; this release does not pin that image yet, 1.6.1 does.

## Upgrade

1. **keyryx is installed by default.** Every launcher (`deploy.sh`, `cloud/gcp`, `cloud/aws`) installs keyryx custody and the witness, mints their root keys and the consumers' bearers once (kept on re-run), and patches wardryx and the record-seal to use custody. The deploy machine needs `openssl`. `--without-keyryx` keeps the previous setting, which is weaker, and the closing report says so; custody, the witness and their keys stay if they were installed.
2. **A record-seal job that failed silently now fails.** A pack that cannot be built fails the job and prints the node's reason; only an empty ledger exits 0. Expect failed record-seal jobs where a pack was failing before (invariant 71, GOTCHAS 151).
3. **The record-seal runs beside the witness.** Both read the records volume, which is ReadWriteOnce, so the record-seal is pod-affined to the witness's node and waits while the witness is down (invariant 70).
4. **With `--typed-risk-signal`, a brokered call with no typed signal is held** for a person (invariant 65).
5. **`--costcrew-ceiling USD`** bounds the crew's spend; the crew keeps its schedule (invariant 66).
6. **wardryx is pinned at v2.4.0 by digest.** The keyryx overlays used to pin v2.3.0 and would have rolled wardryx back.

## What changed

- idryx no longer restarts before tokenfuse writes its stream: the gateway pod precreates `tokenfuse.ndjson` (GOTCHAS 150).
- The approver key is minted once and mounted into the console; wardryx does not require approver statements yet, so no approval is refused while the console is still the pinned v1.1.48 (invariant 67, staged; 1.6.1 sets `WARDRYX_APPROVER_JWKS`).
- The console image workflow checks out its five sources at pinned commits (invariant 68).
- `hub/add-site.sh` reads a digest-pinned image.

## Not measured

- keyryx and the record seal on a live cluster from this tag; the witness's attestations reaching a pack (keyryx v0.1.1 writes them 0600; keyryx v0.1.2 fixes the mode and is pinned by 1.6.1); approver statements end to end; the console image this tag builds, and its signature against the admission policy.
