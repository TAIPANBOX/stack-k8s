# stack-k8s 1.1.6

The gateway, its focus-export sidecar and the control plane move together
to TokenFuse 1.0.3. The gateway retains run and unit reservations when a
request is cancelled after dispatch, reads complete SSE events, and nets
cached tokens correctly. On startup, the gateway seeds a unit's current-month
spend from the control plane and replays a bounded telemetry queue after
transport recovery. The control plane reports a run that goes quiet after an
observed cadence. The event-file open failure is now visible.

## The pinned set, 2026-09-19

As in 1.1.5, with `tokenfuse:v1.0.3` for the gateway and sidecar and
`tokenfuse-control-plane:v1.0.3` for the control plane. No other image moves.

## Limits

- No cluster was run on this pinned set. The 1.1.0 cluster run and these
  static gates do not prove the new combination on a live cluster.
- A gateway restart still loses the process-local run ledger and retained
  reservations. There is no reconciliation route for an unknown provider
  outcome.
- A provider `send` error can still release a reservation after the provider
  received the call. Clean streams without final usage remain under review.
- The control plane has no explicit run-finished signal, so a completed run
  without an outcome tag can produce one medium `run_stalled` incident.
- The raft backend remains compiled out of the shipped gateway image.
