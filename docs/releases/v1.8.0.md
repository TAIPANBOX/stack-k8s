# stack-k8s 1.8.0

A minor release. The stack moves to this wave's service releases, a read of the web now passes the TokenFuse MCP broker so a run is labelled from what it did, the NetworkPolicy says which side of the line it sits on, and the console image carries the two engines its proofs run.

## Upgrade first

1. **`tokenfuse-mcp-broker-keys` needs the scope rules (breaking, on purpose).** `TOKENFUSE_MCP_SECRET_SCOPES` moved from the broker's env into this Secret. A Secret made before this release has no rules, and the broker waits on it until the key is added. `typed/mode.sh door-secrets` mints it on a new cluster and prints a pointer when it keeps an existing Secret. The patch is in the header of `manifests/52-tokenfuse-mcp-broker.yaml`.
2. **Anything other than the broker that called Scopyx directly is refused.** `scopyx-ingress` admits the broker and nothing else. An agent reads the web through `http://tokenfuse-mcp-broker:4200/mcp` with `X-Fuse-Mcp-Upstream: scopyx`, `X-Fuse-Agent-Id`, `x-fuse-run-id` and `params._meta: {"scopyx/key": "{{secret:scopyx_key_<agent>}}"}`. The README section "How an agent reads the web" has the client and the three places a key must agree.
3. **Re-run the launcher, or apply the manifests of this tag.** Each image moves by tag and digest:

## What changed

- **A run is labelled from the act (G2.1).** The broker names Scopyx as an upstream and classifies it `web`, so a read of the web reaches TokenFuse as an observed act. Invariant 78, gate `scripts/scopyx-reads-go-through-the-broker.sh`, 17 teeth cases (#218).
- **The console's incident loop.** `genaryx-console:v1.7.5` assembles a case file for an incident, proves a candidate policy with `wardryx replay` and a candidate budget with `tokenfuse backtest`, routes typed remedies to a person and seals a case as one canonical document. The image copies both engines out of the digests the manifests name, and the console pod joins wardryx's group to read the policy archive. Invariant 79, gate `scripts/console-engines-are-the-stacks.sh` (#219).
- **The NetworkPolicy names its boundary (G2.3).** The header of `30-network-policy.yaml` and the README say the policies cover the pods of `agent-stack`. `agent-tokens/confined-agent` is an optional overlay that puts an agent pod behind `58-agent-tokens-network.yaml`, and `agent-tokens/confine-check.sh` proves it on a live cluster with three probes. Invariant 77 (#215).
- **Docs.** Heraldyx is the mail hole, not the only way out, and the diagram and the counts say what the policy says (#216).

## Measured

- The console image was built for amd64 and arm64 by `console-image.yml` from the tag `v1.7.5`, which exists to build it: a signature is accepted only from a tag, so the image a release pins comes from the tag before it. Both smoke loops ran every bundled tool and both engines, and the digest was read from ghcr.io before it was written here.
- Agent confinement ran on k3d: the overlay's pod reaches vouchryx, the gateway and the broker, a pod with no label in the same namespace does not, and a pod in an uncovered namespace is the control (`evidence/agent-confinement-k3d`).
