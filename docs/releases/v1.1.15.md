# stack-k8s 1.1.15

The console moves to 1.1.14 and the policy plane to 1.1.0, after a run with
both on a three-node cluster.

## What changed

- **`genaryx-console:v1.1.14`** (was v1.1.1) in the console Deployment, the
  `quality-drift` CronJob and the four probe pods of `security-tests.sh`. It
  carries genaryx#81: Felyx's model calls name the agent making them
  (`x-fuse-agent-id`), so a TokenFuse gateway enforcing policy can govern the
  console's own copilot instead of refusing it.
- **`wardryx:v1.1.0`** (was v1.0.3). It adds `POST /v1/filter-tools`, which
  TokenFuse calls only when `TOKENFUSE_TOOLS_PRUNE=shadow`; the decision path
  is unchanged.

## Measured

On 2026-09-27, on a three-node cluster (k3d, 1 server and 2 agents, k3s
v1.36.2, Calico) running the pinned set of 1.1.14 with these two images in place:
verify.sh 16 passed, 0 failed, 1 noted; security-tests.sh 24 passed, 0 failed,
3 noted. The same day, the 1.1.14 console with Felyx pointed at this stack's
own gateway answered questions across the planes, proposed a kill that the
console would not run without a passkey, and was stopped by its run budget
with a 402.

## Upgrade

`kubectl apply -k manifests` rolls the console and wardryx once.

## Not in this release, said plainly

- The manifests still point Felyx at a local Ollama the stack does not ship;
  wiring it to the gateway is a separate change.
- The run was on k3d with a host directory standing in for the RWX volume,
  not on Longhorn.
