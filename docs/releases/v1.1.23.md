# stack-k8s 1.1.23

The 2026-10-04 releases land in the launcher: eight pins move, the gateway gets
an operator ceiling on a run's budget, typed answers can feed a policy hold, and
a verifier watches the event bus. Nothing in it was run on a cluster.

## What changes for an operator

- **A run's budget has a ceiling.** The gateway sets
  `TOKENFUSE_MAX_RUN_BUDGET_USD=5.00`, tokenfuse's own built-in run budget, so an
  ordinary run is unchanged and a budget a caller declares above 5.00 is lowered
  to it. It does not lower a budget the Cloud sets. `--run-budget-ceiling USD` on
  the three deploy scripts changes it; give it on every run, because a re-run
  without it returns the gateway to 5.00.
- **`--typed-risk-signal`** (off by default, needs typryx deployed): typryx's
  `wardryx-proxy` between the MCP broker and wardryx adds the risk class of a
  pending tool call to the decision request, so a `hold_if_signal` rule can hold
  it for a person. No policy is seeded; the README has an example. With the flag
  the broker, which asked wardryx nothing before, asks about every tool call and
  fails closed.
- **The chain verifier.** A CronJob, `agent-conform`, every 15 minutes, in the
  default install. A broken chain on the bus becomes a `chain_broken` event; a
  new break also fails the Job once. It adds no disk.
- **Bus file names** now matter: heraldyx v0.3.0 and idryx v1.1.0 refuse an event
  whose `source` is not allowed for its file. Every stream this launcher names
  already matches, and a gate keeps it so.

## Upgrading

- `TOKENFUSE_MODE` is set to `enforce` explicitly, so tokenfuse v1.5.0's refusal
  of a mistyped mode does not touch a launcher install. A hand-written deployment
  with a wrong value will now exit 2 at start.
- Apply the manifests as usual. `agent-conform` starts at the next quarter hour
  and creates `agent-conform.ndjson` and `agent-conform.state.json` on
  `stack-events`.
- costcrew v0.3.0 halves two decision thresholds (T.anomaly 2,500, T.urgent
  12,500) and refuses an engine no configured gateway fronts. This launcher
  configures no gateway for costcrew, so only the thresholds change: more
  decision requests reach the owner for the same work.
- vouchryx v0.2.0 drops `actor` and `reason` from the public revocation list;
  the gateway reads neither.

## Not proven

No cluster was used. The manifests render and pass `kubeconform --strict`, every
gate passes, and the proxy and the verifier were run as containers against stand-in
inputs, but no pod ran behind these NetworkPolicies, no gateway clamped a call
here, no real chain broke, and no hold was made from a real signal. The ceiling
bounds each run, not an agent's total spend. The verifier holds the bus
read-write; that it writes only its own files is the tool's guarantee.
